# Carepath

Carepath is a browser-based smart health navigation demo. It provides a symptom-guidance chat, a step-by-step symptom assessment, report and attachment demos, and a synthetic doctor-matching and appointment-slip flow.

> **Medical and demo notice:** This project is not a medical device or a substitute for a licensed healthcare professional. Its symptom and report responses are generated by simple keyword rules and have not been clinically validated. Do not use its medication suggestions to diagnose or treat a condition. Doctor, hospital, fee, availability, and appointment information is synthetic demo data; an appointment slip does not reserve a real hospital slot. For emergencies, contact your local emergency service or go to an emergency department.

## Features

- AI-chat-style health copilot for symptom questions, with English, Telugu, and Hindi language options in the interface.
- Guided assessment flow for patient details, symptom category, severity, and duration.
- Heuristic responses for common symptom categories, including emergency keyword alerts.
- Image and document attachment interactions, plus a report-analysis endpoint that categorizes supplied report text using keywords.
- Specialist and hospital listings filtered by symptom and city. The displayed providers and availability are generated from demo data.
- Demo booking flow that generates an appointment ID, OPD token, and printable appointment slip locally in the browser.
- Browser speech input where supported.
- Patient profile and up to 50 medical chat-history entries saved in browser `localStorage`.

## Requirements

- Node.js installed and available as `node` in your terminal.
- A modern browser. Speech input depends on browser support and microphone permission.

There are no external Node.js package dependencies; the server uses Node's built-in modules.

## Run locally

From the project directory, run:

```bash
node server.js
```

Open [http://localhost:3000](http://localhost:3000) in your browser. Stop the server with `Ctrl+C` in the terminal.

The server listens on port `3000`, configured in `server.js`. If that port is already in use, stop the other process or change the `PORT` constant in `server.js`.

## How to use

1. Start in **AI Chatbot Mode** to enter a symptom or health question, or switch to **Step-by-Step Mode** for the guided assessment.
2. Choose a city and symptom category to view the matching demo provider list.
3. Try the attachment and report flows with sample, non-sensitive data.
4. Use the history and privacy controls to review or clear locally saved profile and history data.

The chat flow accepts symptom and wellness messages; the report flow accepts extracted text for keyword-based categorization. Neither flow performs validated diagnosis, OCR-based medical interpretation, or a connection to a real hospital booking system.

## API endpoints

The frontend calls these endpoints on the same local server:

### `POST /api/agent/chat`

Request JSON:

```json
{
  "message": "I have a headache",
  "attachment": null
}
```

`attachment` is optional. The response includes a generated reply, urgency and category fields, and any demo medication information. The server masks some phone-number, Aadhaar-like number, and email patterns in the message before keyword matching; this is not comprehensive privacy protection.

### `POST /api/analyze-report`

Request JSON:

```json
{
  "text": "Sample report text mentioning ECG",
  "fileName": "sample-report.txt"
}
```

The response contains a rule-based category, condition, summary, specialist, and demo medication information. It does not validate or diagnose a real report.

## Privacy

The app stores the profile under `carepath_user` and medical history under `carepath_medical_history` in the current browser's `localStorage`. This data remains on that browser until cleared through the app or browser settings. Avoid entering real personal or medical information into this demo, and do not upload sensitive records. The message masking in `server.js` only covers a few recognizable patterns and should not be treated as anonymization.
